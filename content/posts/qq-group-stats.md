群里人不少，但总觉得说话的永远是那么几个。于是想量化一下：

> 某一段时间里，到底有多少人说过话？发了多少条？谁最活跃？

做完之后长这样：

![统计界面](/images/qq-group-stats-preview.png)

## 数据从哪来

这是第一个卡住的地方。想统计群聊，总得先拿到消息。

最直接的想法是读 QQ 的本地数据库——`nt_msg.db`。翻了翻资料就放弃了：库是加密的，密钥跟登录态绑定，QQ 一更新就可能失效，而且这类工具本身也容易被拿去做别的事。

于是换了个思路，做了两种来源：

| 方案 | 数据来源 | 需要什么 |
| --- | --- | --- |
| 离线版 | QQ 导出的聊天记录 txt | 什么都不用装 |
| 在线版 | NapCat 的 OneBot 接口 | 本地跑着协议端 |

两条路各解决一部分人的需求：大多数人只是偶尔想看看，用导出的文件就够了；已经在挂机器人的，直接用接口更省事。

## 离线版：导出一份记录就行

操作比想象中简单：

1. PC QQ → 左下角三横线 → **消息管理器**
2. 左边选中要统计的群
3. 右键 → **导出消息记录** → 格式选 **txt**
4. 打开程序，选文件、填群人数、选日期

程序解析的是一个很朴素的格式：

```
2026-11-01 12:00:00 小明(10001)
今天好热
```

思路就是**按「时间戳开头的行」切分**：匹配到的行当作消息头，从里面抠出时间和昵称，后面的行都算上一条消息的正文。所以多行消息会被正确合并，不会拆成一堆碎片。

有个细节要处理：QQ 导出可能是 UTF-8，也可能是 GBK。读取时挨个试 `utf-8-sig → utf-8 → gb18030 → gbk`，总有一个能成。

## 在线版：让 NapCat 帮忙翻消息

如果你已经在用 NapCat 挂机器人，只需要在 WebUI 里再开一个 **HTTP 服务器**（端口 3000），程序就能通过 OneBot v11 接口拿数据：

- `get_group_list` —— 群列表
- `get_group_member_list` —— 群成员（用来算活跃比）
- `get_group_msg_history` —— 历史消息

真正麻烦的是第三个：**一次只能拿一页，得自己往回翻**。

```python
seq = 0
while True:
    batch = client.get_group_msg_history(gid, 100, seq)
    if not batch:
        break
    ...
    seq = min(m["message_seq"] for m in batch)
```

翻页的终止条件要小心，写不好就会死循环：如果下一页返回的 `seq` 跟当前一样，说明接口没往前走，必须直接退出。

## 三张图

统计逻辑本身不复杂，难的是**怎么把数字讲清楚**。最后定了三个视角：

| 图表 | 回答什么问题 |
| --- | --- |
| 每日趋势 | 这段时间聊天的热度变化 |
| 发言排行 | 谁在撑起这个群 |
| 活跃比 | 群里有百分之多少的人真的在说话 |

活跃比是 `发言人数 ÷ 群成员总数`，分四档：60% 以上非常活跃、30~60% 比较活跃、10~30% 一般、低于 10% 就算冷清。

拿一个 186 人的群举例，一周 1204 条消息、37 个人发言，算下来活跃比 19.9%——看着热闹，其实八成人一句话没说。

## 踩到的三个坑

**一、分页会卡死**

第一版没加 `seq` 是否前进的判断，接口返回同一页时程序原地打转。加上「next_seq == seq 就退出」才解决。

**二、群人数是「现在」的人**

活跃比的分母取的是当前群成员数，不是统计区间当时的人数。有人这周才进群、有人上周就退了，算出来会有偏差。这一点我在 README 里写明了，只能当参考。

**三、图表中文全是方块**

matplotlib 默认字体不带中文。开头加两行就好：

```python
matplotlib.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei"]
matplotlib.rcParams["axes.unicode_minus"] = False
```

## 代码结构

```
qq-group-stats/
├── main.py            # 在线版界面
├── main_offline.py    # 离线版界面
├── onebot.py          # OneBot 客户端 + 分页
├── local_reader.py    # 导出 txt 解析
├── stats.py           # 统计逻辑（纯函数）
└── charts.py          # 三张图
```

界面用 Tkinter，图表用 matplotlib 嵌进窗口，没有额外的前端框架。

写的时候特意把**统计逻辑抽成纯函数**，这样不用连 QQ 也能测。测试方式是起一个假的 OneBot 服务器，塞 10 条消息进去，验证翻页能不能拿全、活跃比算得对不对：

```
✓ 群列表: 测试群
✓ 拉取消息: 10 条，调用接口 5 次
✓ 活跃比: 30.0%（比较活跃）
```

```powershell
git clone https://github.com/DLCNatsuki/qq-group-stats.git
cd qq-group-stats
python -m pip install -r requirements.txt
python main_offline.py
```

README 里写了详细的两种用法、每个控件怎么填、以及常见问题。

做完这个工具最大的感受是：**数据不难拿，难的是想清楚要回答什么问题**。一开始我只想统计「谁说话最多」，真把图画出来才发现，「有多少人一句话没说」才是更值得看的那个数。
