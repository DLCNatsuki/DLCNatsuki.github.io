# 08 日常维护与排错

> 记录日常命令和踩过的坑，出问题时先来这里查。

---

## 一、日常命令

```bash
# 本地预览（含草稿）
hugo server -D

# 新建文章
hugo new content posts/文章名.md

# 构建
hugo --minify

# 发布
git add .
git commit -m "更新：xxx"
git push
```

### 发布前检查

```bash
# 1. 先拉远端改动（防止冲突）
git pull --rebase origin main

# 2. 看看改了哪些文件
git status

# 3. 提交推送
git add -A
git commit -m "说明"
git push
```

## 二、报错对照表

### 启动与构建

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `hugo: command not found` | 没装或没进 PATH | 重装，或重开终端 |
| `Error: module "PaperMod" not found` | 主题没装 | 检查 `themes/PaperMod` 是否存在 |
| `failed to load config` | `hugo.toml` 语法错 | 检查引号、括号 |
| `port 1313 already in use` | 上次服务器没关 | `--port 8080` 或杀进程 |
| `TOCSS: failed to transform` | 用了非 extended 版 | 重装 Extended |
| `execute of template failed` | 模板语法错 | 看报错行号，核对变量 |

### 内容

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 文章 404 | 草稿 / 未来日期 | 改 `draft`、`date` |
| 文章出现在首页但点开 404 | `slug` 与文件名冲突 | 去掉自定义 `slug` |
| 图片裂图 | 路径不对 | `static/x.jpg` → `/x.jpg` |
| 中文标题 URL 乱码 | 用了标题当 slug | 加 `slug = 'english'` |
| 标签页空 | 没写 `tags` | front matter 加数组 |

### 部署

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| 页面 404（刚部署完） | Pages Source 没设成 Actions | Settings → Pages |
| `! [rejected]` | 远端有新提交 | `git pull --rebase` |
| `refusing to allow a PAT to create/update workflow` | PAT 缺 workflow 权限 | 重新生成 token |
| Actions 红叉 | 看日志第一行 | 通常是版本或主题问题 |
| 部署成功但没变化 | 浏览器缓存 | `Ctrl+F5` |

### Git

| 报错 | 解决 |
| --- | --- |
| `fatal: not a git repository` | 不在项目目录，或没 `git init` |
| `Please tell me who you are` | `git config --global user.name/email` |
| `Permission denied (publickey)` | SSH key 没配，改用 HTTPS |
| `failed to push some refs` | 先 `git pull --rebase` |

## 三、Git 冲突处理

多人/多设备编辑时最常见。

```
<<<<<<< HEAD
你本地的内容
=======
远端的内容
>>>>>>> origin/main
```

**解决步骤**：

1. 打开冲突文件，手动保留想要的内容，删掉 `<<<<<<<`、`=======`、`>>>>>>>` 标记
2. `git add 冲突文件`
3. `git rebase --continue`（或 `git commit`）

**不想处理冲突**（放弃本地改动）：

```bash
git checkout -- 文件名     # 恢复单个文件
git reset --hard origin/main   # 全盘放弃本地（危险）
```

## 四、缓存问题排查

**改了配置/样式没生效**，按顺序排除：

1. 浏览器硬刷新：`Ctrl + F5`（Mac：`Cmd + Shift + R`）
2. 重启 `hugo server`
3. 删掉 `public/` 和 `resources/` 重新构建：
   ```bash
   rm -rf public resources
   hugo --minify
   ```
4. 检查是不是改错了文件（比如改的是 `themes/` 而不是项目 `layouts/`）

## 五、备份与恢复

```bash
# 看历史
git log --oneline -20

# 回退到某个提交（本地）
git reset --hard 提交哈希

# 只回退某个文件
git checkout 提交哈希 -- 文件路径

# 撤销最近一次提交但保留改动
git reset --soft HEAD~1
```

> 站点源码就是全部，Git 本身就是最好的备份。
> 重要图片建议另外存一份网盘。

## 六、多设备同步

在另一台电脑上：

```bash
git clone https://github.com/用户名/用户名.github.io.git
cd 用户名.github.io

# 主题如果是 submodule
git submodule update --init --recursive
```

之后两台机器都遵守：**先 pull，再改，再 push**。

## 七、性能与体积

| 问题 | 优化 |
| --- | --- |
| 首页越来越大 | 限制首页文章数 `pagination.pagerSize` |
| 图片太大 | 压缩（<300 KB），或转 WebP |
| 构建慢 | 文章多了以后正常，Hugo 仍比 Hexo 快 10 倍 |
| 仓库变大 | 别提交 `public/`、`resources/` |

## 八、检查清单（每次发布前）

```
□ hugo server -D 本地预览正常
□ 新文章 draft 已改 false
□ 图片路径正确
□ git pull --rebase 成功
□ git status 确认没有意外文件
□ commit message 说清楚改了什么
□ push 后 Actions 变绿
```
